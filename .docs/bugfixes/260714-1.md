Update the MCP tool description, workflow guidance, and behavioural tests so user-facing cache-currentness / “as of” caveats use the relevant per-table `last_run` values (normally the oldest relevant value for a multi-table answer), or an endpoint's `cache_synced_at` when present. Describe `high_water` only as wa's sync-mode-specific source-progress watermark: it may be a source-change time, a full-refresh snapshot time, or empty, and it must never be phrased as “synced through” or used to judge when the cache was refreshed. Update the wa dependency to a version whose OpenAPI field descriptions expose these semantics, and add an LLM-facing regression that distinguishes an old unchanged-source `high_water` from a recent `last_run`.

# Bug fixes 2026-07-13

- [x] Even with an “exact filter” present, an empty or whitespace-only term currently bypasses guardTerm and will attempt an upstream call with an empty path parameter (e.g. /search/sample/). Since term is always a required path segment, reject empty/blank terms before deciding whether the 3-character minimum applies. mlwh_count_samples has the same issue as mlwh_search_samples: providing an “exact filter” allows bypassing the 3-character minimum, but it should not allow an empty/blank term because the upstream route still requires a non-empty :term path parameter.
  - PR: #3

  - Count thread: `PRRT_kwDOQeEIlc6QSvz7`; comment: `3568453448`; review SHA: `668c52db00bdc39a0920f170e9f8a295d9142130`
  - Updated `internal/mlwh/tools_search.go` with shared nonblank-term validation before the exact-filter minimum-length exemption.
  - Added public MCP regressions in `internal/mlwh/tools_search_test.go` for blank list/count terms and preserved nonblank two-character exact-filter searches.

- [x] QueryParameterValues.UnmarshalJSON currently treats JSON null as a valid scalar string (Go unmarshals null into "" without error), so `query_params: {"platform": null}` becomes a single empty value and can silently send `platform=` to the upstream endpoint. This should be rejected explicitly to match the schema's `oneOf` (string or array of strings) and avoid surprising upstream errors.
  - PR: #3
  - Thread: `PRRT_kwDOQeEIlc6QS-qZ`; comment: `3568535842`; review SHA: `395dd2252f67395aa58a97dafc0b7811f2e36005`; review: `4682313913`
  - Decoded scalar values through `*string` so JSON `null` is rejected without rejecting valid strings.

- [x] `QueryParameterValues.UnmarshalJSON` still accepts `{"platform":["illumina",null]}`. The `[]string` decode silently converts the null element to `""` because Go ignores JSON null for primitive string targets. This violates the schema's array `items: {"type":"string"}` contract and can send `platform=` upstream. Add a regression for null within an array and reject null elements while preserving valid array order.
  - Discovered by the independent reviewer while verifying comment `3568535842`.
  - Decoded arrays through `[]*string`, rejecting null elements while preserving valid value order.
  - Added behavioral JSON-input regressions for valid scalar and ordered-array values plus both null forms.
